DovetailJoint

Section titled “DovetailJoint”

A DovetailJoint item declares a joint kind: a typed extension point that other code can contribute to without knowing who applies it. One line in a project file becomes a joint interface, its async twin, the delegates for both, an Apply extension that runs every joint of the kind, and a method on DovetailContextBuilder that registers a delegate. Dovetail’s own joints (ISetupJoint, IServiceJoint, ILoggingJoint, IConfigurationJoint, IHostCreatedJoint<THost>) are declared this way, and so are those of Serilog, OpenTelemetry and Aspire.

The item is expanded by MSBuild targets, not by the Roslyn source generator: the C# is written to obj/ before the compiler runs, so you can open it in your IDE like any other source file.

Who declares one, and when

Section titled “Who declares one, and when”

A package or application that owns something other code should be able to configure declares a joint kind for it. Serilog’s package declares Serilog for LoggerConfiguration, so any library can add a sink; Sample.Core declares DatabaseConfigurator for its own IDatabaseConfigurator, so other assemblies can add tables and views.

Declare one when:

  • you hand an object to other code at one point in startup (a builder, a configuration object) and want every library to be able to contribute to it without referencing your application or each other;
  • you are prepared to call Apply{Name} yourself at that point. A joint kind does not run by itself: SerilogJoint calls loggerConfiguration.ApplySerilog(...) once it has created the LoggerConfiguration.

Do not declare one when:

  • you only want to run code at startup. Implement an existing joint such as IServiceJoint or ILoggingJoint instead, as described in Defining Dovetails;
  • Dovetail or one of its packages already declares a joint for the type you have: Joinery.Dovetail covers IServiceCollection, IConfigurationBuilder and ILoggingBuilder, and Joinery.Dovetail.Hosting covers the host builders.

The item is read by the targets that ship in Joinery.Dovetail, so the project that declares it must reference that package (Joinery.Dovetail.Sdk adds the reference for you). The generated types are public, so anything that references your project sees them as ordinary API.

Declaring a joint

Section titled “Declaring a joint”

The item’s Include is the joint’s name. It becomes part of every generated type name, and of the generated file names, so it has to be a valid C# identifier, and it must be unique in the project.

That is the smallest useful declaration: a joint that is handed only the IDovetailContext. Everything else is metadata.

Metadata

Section titled “Metadata”

Metadata is optional unless stated. A name the item does not read is ignored without a warning, so a misspelling falls back to the default (NMAmespace leaves Namespace at its default). Boolean values are compared with true ignoring case; any other non-empty value counts as false.

MetadataDefaultWhat it changes
Namespace$(RootNamespace).JointsThe namespace of every generated type, and so the namespace consumers import. Joints of one package usually share one, as Joinery.Dovetail.Joints does.
ProvideConfigurationempty (false)true adds an IConfiguration configuration parameter to Register, after the context. The value passed is context.Configuration; Apply{Name} takes no configuration parameter.
ProvideServicesempty (false)true adds an IServiceCollection services parameter to Register, after the configuration if there is one. With no ParameterType it is also the subject of Apply{Name}.
ParameterTypeemptyThe type of one more Register parameter, the last one. It becomes the subject of Apply{Name}. Written into the generated code exactly as given; see common mistakes.
ParameterNameparameter when ParameterType is setThe name of that parameter, as it appears in Register and in Apply{Name}. Ignored without ParameterType.
BuilderMethodNameConfigure{Name}The name of the extension method on DovetailContextBuilder that registers a delegate. Service is declared with BuilderMethodName="ConfigureServices".
GenericParameteremptyA type parameter name that makes the joint generic: I{Name}Joint<in T>, Apply{Name}<T>, Configure{Name}<T>. ParameterType may be this name, and then the parameter is typed T.
GenericConstraintemptyThe constraint of that type parameter: where T : {GenericConstraint}. Written as given. Ignored without GenericParameter.
GenericVariancein when GenericParameter is setThe variance modifier on the type parameter of the generated interfaces and delegates. Ignored without GenericParameter. When ParameterType is the type parameter, only in compiles; see common mistakes.
IsAsynctruefalse generates only the synchronous joint. No I{Name}AsyncJoint, {Name}AsyncJointDelegate or async Configure{Name} overload, no DovetailJointAsync.{Name}.g.cs, and Apply{Name} returns void instead of ValueTask.
ReturnFirstArgumentempty (false)true makes Apply{Name} return ValueTask<IDovetailContext>, the context after the joints ran. It compiles only for a joint whose subject is the context itself: no ParameterType and no ProvideServices. With IsAsync false the result is discarded.

The parameter lists

Section titled “The parameter lists”

Register takes, in this order, only the parameters that apply:

  1. IDovetailContext context, always;
  2. IConfiguration configuration, with ProvideConfiguration;
  3. IServiceCollection services, with ProvideServices;
  4. {ParameterType} {ParameterName}, with ParameterType;
  5. CancellationToken cancellationToken = default, in the async twin only.

Apply{Name} is an extension method. Its subject (the this parameter) is the ParameterType if there is one, otherwise the service collection if ProvideServices is set, otherwise the context. After the subject come the context (unless it is the subject), the service collection (if ProvideServices and ParameterType are both set) and, last, a CancellationToken cancellationToken = default.

What is generated

Section titled “What is generated”

Each joint is written to $(IntermediateOutputPath), which is obj/<Configuration>/<TargetFramework>/, as ordinary Compile items:

FileContents
DovetailJoint.{Name}.g.csI{Name}Joint, its delegate, Apply{Name} and the Configure{Name} method for the delegate.
DovetailJointAsync.{Name}.g.csI{Name}AsyncJoint, its delegate and the Configure{Name} method for it. Not written when IsAsync is false.

Everything is declared in Namespace:

TypeWhat it is
I{Name}JointThe interface a contributor implements: void Register(...). Mark the class [DovetailExport] so it is discovered; see Defining Dovetails.
{Name}JointDelegateA delegate with the same parameters, for registering a lambda.
I{Name}AsyncJointThe async twin: ValueTask Register(..., CancellationToken cancellationToken = default).
{Name}AsyncJointDelegateThe async delegate.
{Name}JointExtensionsA static partial class holding Apply{Name}, which runs every registered I{Name}Joint and I{Name}AsyncJoint through the executor.
{Name}HostBuilderExtensionsA static partial class with an extension(DovetailContextBuilder) block: Configure{Name}(delegate, priority = 0, category = null, hostType = Undefined), once for each delegate type. Generated for every joint, including the ones whose subject is the context.

The interfaces derive from IDovetailJoint and, like the delegates, carry [JointName("{Name}")].

The rarely needed values

Section titled “The rarely needed values”

Nothing in src/ or sample/ sets ProvideConfiguration, GenericConstraint, IsAsync or ReturnFirstArgument, so these declarations are compiled, and the signatures they generate checked, by test/Joinery.Dovetail.Sdk.Tests/DovetailItemReferenceTests.cs (it declares exactly these items):

  • Minimal is handed only the context, and its types are in worker.Joints (the test project’s RootNamespace is worker).
  • Wired registers Register(IDovetailContext context, IConfiguration configuration, IServiceCollection services), and its ApplyWired is an extension on IServiceCollection.
  • Builder is applied with logging.ApplyBuilder(context, services) and registered with ConfigureTheBuilder(...).
  • Generic declares IGenericJoint<in TBuilder> where TBuilder : IHostApplicationBuilder.
  • Covariant has a type parameter that Register does not take, so out compiles, and an ICovariantJoint<string> is an ICovariantJoint<object>.
  • SyncOnly has no async twin, and context.ApplySyncOnly() returns void but still takes a CancellationToken.
  • Chained.ApplyChained returns the context. ChainedSync has no async twin and ApplyChainedSync returns void: the context the executor returns is discarded.
  • Unprefixed is written into the generated code as Microsoft.Extensions.Logging.ILoggingBuilder, with nothing in front of it.
  • Ignored generates the same code as Minimal: ParameterName without a ParameterType, GenericConstraint and GenericVariance without a GenericParameter, and the misspelled NMAmespace all do nothing, so its types are in worker.Joints.
  • Shouting and NotTrue are synchronous: False and no are not true. Shouting also takes the service collection, because TRUE is true in any case.

Common mistakes

Section titled “Common mistakes”
  • ParameterType and GenericConstraint are written exactly as you give them. Dovetail puts nothing in front of them, so write the type fully qualified with global::, as every package in this repository does: global::Serilog.LoggerConfiguration. A bare Serilog.LoggerConfiguration compiles too, until a namespace that encloses the generated code has a member called Serilog, which then captures the name. A project that declares Custom.Microsoft does that to a bare Microsoft.Extensions.Logging.ILoggingBuilder in a joint in Custom.Joints, and the build fails with CS0234.
  • A generic joint’s ParameterType may be its GenericParameter, and then must be written bare, as TBuilder: a global:: in front of it names a type in the global namespace, not the type parameter.
  • GenericVariance="out" does not compile when the type parameter is the ParameterType (CS1961): it is an input of Register, so a covariant one is invalid, and in, the default, is the only value that compiles. With a GenericParameter and no ParameterType, Register does not take the type parameter, and out compiles.
  • ReturnFirstArgument only suits a joint whose subject is the context. With a ParameterType or ProvideServices the generated Apply{Name} tries to return the IDovetailContext as a ValueTask<ILoggingBuilder> (or whatever the subject is), which fails with CS0029.
  • ParameterName without a ParameterType, and GenericConstraint or GenericVariance without a GenericParameter, do nothing. The metadata is ignored, with no warning.
  • A misspelled metadata name is ignored too. src/Joinery.Dovetail.Aspire.Testing writes NMAmespace, so its namespace is the default, which happens to be the one it meant.
  • IsAsync="false" leaves contributors no way to do async work for the kind, since there is no I{Name}AsyncJoint to implement. Apply{Name} still takes a CancellationToken, which the synchronous call ignores.
  • The name is part of every generated file and type name, so declare each joint once.
